# Example: From Frontend to Full-Stack

> 一个完整的使用示例：前端开发者小明，用 CareerOS 从 `init` 到拿到第一个项目推荐的完整流程。
> 对话内容为模拟展示，用于说明 CareerOS 的输出形态与交互方式。

---

## Scene / 场景

- **用户背景**：前端工程师，React + TypeScript 经验 3 年
- **目标**：转全栈开发（Node.js 方向）
- **可投入时间**：每周约 10 小时
- **学习节奏**：偏实操，不喜欢看大量理论

---

## Part 3 · 项目生成（/CareerOS generate project）

```
用户: /CareerOS generate project

CareerOS: 【项目生成器】完成 ✅

推荐项目：TaskFlow —— 企业级任务管理系统
这是一套工业级复杂度的实战项目，覆盖你的全部关键缺失环节。

技术栈：
Node.js + TypeScript + Fastify + PostgreSQL + Redis + Docker + GitHub Actions

难点预测：
- JWT + Refresh Token 双令牌认证
- 事务性数据库建模（用户 / 项目 / 任务 / 评论 四张核心表）
- Redis 缓存热点任务列表的一致性
- Docker Compose 多服务编排 + CI 自动测试

验收标准：
- [ ] 用户注册 / 登录，支持令牌自动刷新
- [ ] 任务的 CRUD 与状态流转（Todo → Doing → Done）
- [ ] 关键接口 P95 延迟 < 200ms（附压测脚本）
- [ ] docker compose up 一键启动，CI 通过全部测试

难度评估：★★★☆☆（以你当前水平，预计 4–6 周）
```

## Part 4 · 语境感知（Context-Aware）

```
用户: 我还没用过 Redis，这个项目会不会太难？

CareerOS: 不会。我会把 Redis 部分拆成渐进增强阶段，你随时可以暂停：

- 阶段一（2 周）：PostgreSQL 完成核心功能，交付一个完整可展示的项目
- 阶段二（+1 周）：引入 Redis 缓存热点数据，学习缓存一致性
- 阶段三（+1 周）：可选，引入任务队列处理异步通知

每个阶段都有独立验收标准。完成阶段一，你就已经有一份能写进简历的作品；
做完阶段三，后端能力雷达预计从 5/10 提升到 8/10，Node.js 缺口基本闭合。

用户: 好，那我从阶段一开始。
```

---

## 要点总结

- `init` 只问必要信息，不做无意义盘问
- `analyze` 输出可量化的差距，而不是空泛的"你还需努力"
- `generate project` 给的是**工业级项目**，附技术栈、难点、验收标准和难度评级
- 任何一步都根据用户水平动态调整（Context-Aware），绝不推荐过难或过易的任务
